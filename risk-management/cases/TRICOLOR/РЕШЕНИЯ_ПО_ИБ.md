# Триколор — варианты решений по ИБ для цифрового медиабизнеса

**Статус: открытый учебный кейс, НЕ аудит компании.** Защита публичных веб- и мобильных сервисов, доступа пользователей, лицензированного контента, бренда, партнёрских интеграций и операционных процессов. Реальное наличие инфраструктуры, контролей или уязвимостей не проверялось.

## Декомпозиция
| Бизнес-объект | Возможное негативное последствие | Класс решения |
|---|---|---|
| Бренд и цифровой контент | Поддельные ресурсы, распространение нелегальных копий, ущерб клиентам и правообладателю | Digital Risk Protection, Brand Protection, OSINT, юридический процесс |
| Личный кабинет / мобильный клиент | Компрометация учётной записи, злоупотребления бизнес-логикой | MFA, risk-based authentication, antifraud, API security |
| Публичные API и интеграции | Неавторизованное обращение к данным, отказ сервиса | API gateway, object-level authorization, rate limiting, WAF, тестирование |
| Канал доставки контента | Несанкционированное распространение, деградация доступа | DRM, watermarking, CDN/DDoS protection, контроль ключей |
| Учётные записи сотрудников / подрядчиков | Неконтролируемые привилегии | SSO/MFA, PAM, JIT, пересмотр доступов |
| Серверы, контейнеры и разработка | Изменение ПО, эксплуатация уязвимости | EDR/XDR, SAST/SCA/DAST, SBOM, container scanning, secrets scanning |
| SOC и реагирование | Позднее обнаружение и увеличение ущерба | Централизованные журналы, SIEM, SOAR при целесообразности, IR playbooks |
| Персональные данные и договорные обязательства | Несоблюдение требований | Классификация, минимизация, DLP по необходимости, шифрование, управление сроками хранения |

## Практические пакеты

### P0 — до масштабных закупок (первые 30 дней после старта проекта)
1. Утвердить владельцев активов, бизнес-цели, границы и критерии риска.
2. Инвентаризация публичных доменов, брендов и официальных ресурсов только по открытым источникам / собственным подтверждённым реестрам.
3. Организовать канал сообщения о фишинговых/поддельных ресурсах, сбор законных доказательств, юридически корректное уведомление площадок, регистраторов и хостеров.
4. Проверить **на согласованном тестовом стенде** управление доступом API, защиту сессий, MFA для сотрудников, журналирование и резервное восстановление.
5. Установить ключевые события и SLO: время обнаружения, время эскалации, доля проверенных активов, полнота логирования.
6. Назначить ответственность за принятие остаточных рисков. Формализовать процесс исключений.

### P1 — 30–90 дней
- Пилот внешнего мониторинга (brand protection / DRP) с ручной верификацией совпадений и ложных срабатываний.
- Подключить защищаемые публичные сервисы к WAF/API security и DDoS-провайдеру **при наличии подтверждённой потребности**.
- Security gates в CI/CD: SAST, dependency/container/secrets scanning, ручные проверки критичных изменений.
- Пилот IAM/PAM для привилегированных и партнёрских доступов.
- SOC use cases: массовые аномальные авторизации, административные операции, необычная выдача токенов, события по правам на контент.

### P2 — 90–180 дней
- Расширить проверенные контроли, внедрить контроль ключей DRM и маркировку контента там, где применяется соответствующая модель распространения.
- Настроить автоматизированную обработку подтверждённых сигналов с обязательным review для юридически значимых действий.
- Регулярно проводить учения по реагированию, восстановлению и инцидентам с компрометацией аккаунтов.
- Пересмотреть реестр рисков на основе фактических результатов пилотов.

## Варианты закупки/реализации
| Контур | Минимальный вариант | Продуктовый/корпоративный вариант | Выбирать по |
|---|---|---|---|
| Мониторинг бренда | Собственные OSINT-поиски + трекер обращений | DRP/brand protection сервис | Полнота, ложноположительные сигналы, юридический workflow, хранение данных |
| API | Open-source gateway + прикладные проверки авторизации | WAF + API discovery/protection | Реальный трафик, поддержка, SLA, TCO |
| SOC | Логирование + конкретные правила + triage | SIEM/XDR/SOAR | Источники событий, компетенции команды, нагрузка |
| Разработка | Semgrep CE, Gitleaks, Trivy, OWASP ZAP на тестовом стенде | Коммерческий AppSec/ASPM стек | Покрытие языков, шум, секреты, стоимость эксплуатации |
| Привилегии | MFA, least privilege, ручная ревизия | PAM/JIT/JEA | Число админов, интеграция, журналирование |
| Контент | Пересмотр прав и контроль утечек | DRM + watermarking + защищённая доставка | Тип лицензий, доступные клиентские платформы, масштаб |

**Стоимость** без обследования и коммерческих предложений не вычисляется достоверно. На стадии ТЭО сравнить 3–5-летний TCO: лицензии, внедрение, инфраструктура, персонал, сопровождение, обучение, рост нагрузки и юридические расходы.

## Приёмка
- Для каждого риска: владелец, доказанный контекст, выбранная мера, критерий результата, дата проверки.
- Пилоты: чёткая тестовая выборка, false-positive rate, покрытие, время реакции, эксплуатационная нагрузка.
- Действия против внешнего контента только на законных основаниях с проверкой принадлежности прав; никакого воздействия на сторонние системы.
- Запрет публикации ПДн, внутренних IP, токенов, уязвимостей и журналов реальных организаций.

## Нормативная связка
ISO/IEC 27005 — управление рисками; ISO/IEC 27001 — система менеджмента; ФСТЭК 05.02.2021 — методика оценки угроз в применимой области; 152-ФЗ и 187-ФЗ — только в тех случаях, когда объект/деятельность подпадают под применимые требования; OWASP API Security Top 10 2023 — перечень распространённых классов рисков API.
