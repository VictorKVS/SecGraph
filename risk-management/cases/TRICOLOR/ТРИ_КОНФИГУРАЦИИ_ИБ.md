# Три проекта ИБ: МИНИМУМ / ВЗВЕШЕННЫЙ / МАКСИМУМ

> Публичное учебное ТЭО. «Триколор» используется как пример профиля цифрового медиабизнеса. Нет доступа к внутренней инфраструктуре, данным об инцидентах, текущих системах защиты или фактическим затратам. Все решения предварительны.

## Цель
Минимизировать число операторов **рутинного мониторинга**, но не утрачивать покрытие, независимый контроль, юридическую проверку и безопасное реагирование. Использовать единое модульное ядро FATHER + SecGraph и OSINT_TRICOLOR как отраслевую конфигурацию. Автоматизация не означает, что отсутствие людей обеспечивает 24/7 SOC.

## Общая архитектура
Источники (разрешённый OSINT / DRP / IAM / API / WAF / EDR / CI) → ingestion → нормализация → дедупликация → корреляция → граф активов/угроз/рисков SecGraph → правила + AI-assist → очередь кейсов → плейбуки → контроль полномочий → аудит и метрики.

### Важные границы
- Разведка только по открытым источникам и собственным разрешённым активам; тестирование только с письменным разрешением.
- LLM не принимает окончательных решений о юридических обвинениях, жалобах, необратимых блокировках, увольнениях или принятии высоких рисков.
- Вредоносные/внешние материалы считаются недоверенным вводом, защита от prompt injection, PII redaction, ограничение прав инструментов.
- Автодействия: allowlist, TTL, лимиты, dry-run, идемпотентность, ручной override, rollback, полная трассировка.

## A. МИНИМУМ
Назначение: быстрый пилот для защиты бренда, OSINT, контроля внешних сигналов и формирования risk register.

Состав: Python collectors / расписание задач / легальная OSINT-инвентаризация / PostgreSQL / правила дедупликации / минимальный case tracker / уведомления / дашборд / экспорт документов. CI: Gitleaks + Semgrep + Trivy. MFA для операторов. Базовые API/WAF меры только по результатам обследования. Развёртывание изолированного тестового стенда.

Штат **для ограниченного пилота**: условно 2–3 FTE (ИБ-лид/аналитик, инженер автоматизации, частичное участие юридической и ИТ-функции). Не гарантирует круглосуточный контроль.

Автоматически: сбор, дедупликация, базовая скоринговая оценка, формирование карточки и черновика отчёта.
Вручную: спорные случаи, претензии, существенные блокировки, принятие остаточного риска.
Недостатки: ограниченная корреляция, внешнее покрытие и устойчивость.

## B. ВЗВЕШЕННЫЙ (РЕКОМЕНДУЕМЫЙ)
Назначение: наиболее рациональная комбинация полноты процессов и нагрузки на персонал.

Состав: из A + единый брокер событий + SIEM (пилот по приоритетным источникам) + SOAR-lite (плейбуки) + детерминированная маршрутизация кейсов + AI-assisted triage с проверкой источников + IAM/PAM при подтверждённой потребности + WAF/API мониторинг + централизованный аудит + SecGraph risk engine. Risk-based controls по подтверждённым рискам, а не универсальная закупка всего стека.

Штат **плановая гипотеза**: 3–5 FTE на выделенную команду программы, при доступной эксплуатации и юристах; выделенный 24/7 SOC потребует отдельного решения или MSSP.

Автоматически: ingestion, кластеризация, enrichment, приоритизация, формирование рекомендаций, безопасные низкорисковые действия из allowlist, публикация отчётности и KRI.
По согласованию: обращения к площадкам, блокировка внешних ресурсов, сложные изменения правил WAF, высокие риски.
Зависимости: каталог активов, роли, качество логов, резервирование, test harness.

## C. МАКСИМУМ
Назначение: широкий набор сервисов, высокое покрытие и сложные корреляционные сценарии.

Состав: из B + DRP-комплекс + XDR/EDR coverage + зрелая SIEM/SOAR оркестрация + PAM/JIT + API security + antifraud при необходимости + continuous controls monitoring + продвинутые DLP / DRM / watermarking **если обоснованы** + отказоустойчивая платформа данных, резервный контур, ML/LLM evaluation, Purple Team.
Штат **гипотеза**: 6–10 FTE выделенной команды интеграции и аналитики, плюс отдельное круглосуточное реагирование/дежурство либо внешний MSSP. Высокая стоимость интеграции и эксплуатации.
Автоматически: сквозной workflow, расследовательские графы, риск-оценка, анализ трендов, резервные очереди, отчётность и частичные ремедиации.
Риски: vendor lock-in, поток ложных сигналов, ошибки автоматизации, затраты на сопровождение и инфраструктуру.

## Ресурсы и стоимость
До сбора входных параметров нельзя корректно утверждать цены в рублях. Использовать **расчётную модель** (см. ТЭО): люди, лицензии, инфраструктура, внедрение, облако/связь, сопровождение, юридическая обработка, резерв 15–25% (допущение), изменение масштаба. Три коммерческих предложения по каждому критичному платному компоненту; отдельно учитывать тарифы и санкционные ограничения.

## Бизнес-процесс
1. Business owner задаёт цели, риск-аппетит и последствия.
2. ИБ + архитектор определяют границы, активы и негативные события.
3. Правила и модели оценивают сигналы, аналитик проверяет качество.
4. SecGraph формирует риск, варианты мер, стоимость/эффект.
5. Бизнес-владелец утверждает бюджет и остаточный риск.
6. Пилот подтверждает эффективность, затем проводится поэтапное расширение.

## KPI пилота — гипотезы
- ≥90% повторяющихся сигналов сводятся в существующие кейсы (тестовая цель; проверять отсутствие ложных объединений).
- ≥70% карточек попадают в очередь без ручного ввода.
- ≥95% автоматических действий имеют полный журнал.
- 100% высокорисковых внешних/необратимых действий требуют санкционированного решения.
- Не ухудшать долю пропущенных критичных событий относительно контрольного набора.
Числа предварительные, обязателен согласованный тестовый набор и baseline.

## Решение
Стартовать с A как технического каркаса, утвердить B как целевую архитектуру. На C переходить только по доказанным требованиям масштабирования и оправданному TCO.
