# SecGraph KB Core Specification

## 1. Назначение
Модуль базы знаний является ядром платформы SecGraph.
Он предназначен для хранения, связывания, анализа и аудита сущностей информационной безопасности.

## 2. Цель модуля
Обеспечить единое структурированное хранилище для:
- угроз
- уязвимостей
- мер защиты
- нормативных требований
- техник атак
- активов
- рисков

## 3. Что модуль должен добиться
Модуль должен:
- хранить сущности в едином формате
- хранить связи между сущностями
- поддерживать аудит изменений
- обеспечивать доступ через API
- быть основой для web-интерфейса и автоматизации

## 4. Как модуль достигает цели
Модуль реализуется через следующие сущности:
- kb_nodes
- kb_edges
- audit_log
- context_rules

## 5. Входные данные
- данные от аналитика
- данные из парсеров документов
- данные из OSINT-модулей
- данные из внешних источников знаний

## 6. Выходные данные
- структурированные записи базы знаний
- граф связей
- журнал аудита
- данные для API и web UI

## 7. Бизнес-правила
- каждая сущность должна иметь тип
- каждая сущность должна иметь внутренний уникальный идентификатор
- изменение сущности должно фиксироваться в audit_log
- связь между узлами должна иметь тип отношения
- связь может иметь вес доверия
- мягкое удаление предпочтительнее физического удаления

## 8. Требования к безопасности
- все операции записи должны логироваться
- структура должна поддерживать RBAC
- история изменений должна быть доступна для аудита
- поля должны валидироваться до записи в БД

## 9. Требования к тестированию
Необходимо проверить:
- создание узла
- обновление узла
- мягкое удаление узла
- создание связи
- получение связей
- запись в audit_log

## 10. Критерии готовности
Модуль считается готовым, если:
- таблицы созданы
- ORM модели работают
- API возвращает данные
- audit_log заполняется
- тесты проходят успешно

После утверждения спецификации создаётся документ тестов:
